# PRD — Product Requirements

> **Authored by humans.** The Planner reads this. The Generator and Estimator may read it on demand.
>
> Replace this scaffold with the real PRD before running the harness on real work.

## Suggested sections

1. **Problem** — who has it, in what context, why now.
2. **Outcome** — what changes for the user when this ships. Stated as a measurable difference, not a feature list.
3. **Scope** — what is in.
4. **Non-goals** — what is explicitly out, with rationale (so the Planner does not silently scope it back in).
5. **Constraints** — non-negotiables: compliance, performance, deadlines, integration surfaces.
6. **Success metrics** — how we will know this worked.
7. **Open questions** — things the team has not yet decided. The Planner watches this list and asks the human when one becomes blocking.
